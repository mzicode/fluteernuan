# Customer IM 源码目录说明

本文用于说明源码交付包的主要目录、技术栈和阅读顺序。最终实际交付文件以包内 `MANIFEST-SHA256.txt` 为准；未出现在清单中的本地缓存、构建产物、凭据、签名文件、日志、数据库备份和用户上传数据不属于源码交付物。

## 一、源码总体组成

| 路径 | 技术/类型 | 主要内容 | 建议入口 |
| --- | --- | --- | --- |
| `lib/` | Flutter / Dart | Android、iOS、Web、Windows、macOS 共用的客户端业务源码、页面、状态管理、模型和网络访问 | `lib/main.dart` |
| `android/` | Android / Gradle | Android 工程、原生能力接入、权限、资源和构建配置模板 | `android/app/` |
| `ios/` | iOS / Xcode | iOS 工程、原生能力、权限、通知、签名能力声明和测试 | `ios/Runner/` |
| `windows/` | Windows / C++ / CMake | Windows Runner、安装器和桌面端构建配置 | `windows/runner/`、`docs/Windows远程打包成功经验.md` |
| `macos/` | macOS / Xcode | macOS Runner、权限能力和桌面端构建配置 | `macos/Runner/` |
| `web/` | Flutter Web | Flutter Web 入口、图标、PWA 配置和第三方浏览器资源声明 | `web/index.html` |
| `backend/` | Go / Gin | REST API、WebSocket、认证、消息、群组、钱包、机器人、任务、迁移和服务端测试 | `backend/cmd/server/` |
| `admin/` | Vue / TypeScript | 运营管理后台、权限、用户/内容/财务/系统配置等管理页面 | `admin/src/` |
| `admin-kf/` | Vue / TypeScript | 客服管理后台、工作台、客户与客服资料、快捷回复等功能 | `admin-kf/src/` |
| `assets/` | 静态资源 | 客户端图片、字体、动画和其他随源码构建的资源 | `pubspec.yaml` 的 `assets` 配置 |
| `official-site/` | HTML / CSS / JavaScript | 通用官网、帮助、支持和隐私静态页面 | `official-site/index.html` |
| `docker/`、`compose.yaml` | Docker Compose | API、数据库、中间件和前端服务的容器部署模板 | `compose.yaml` |
| `scripts/` | PowerShell / Python / Shell | 构建、部署、文档生成、迁移、验收和维护脚本 | 先阅读脚本头部参数说明 |
| `examples/` | Go / Node.js / Python | 机器人接口等能力的最小接入示例 | 各语言示例入口文件 |
| `integration_test/`、`test/`、`test_driver/` | Dart 测试 | 客户端集成测试、单元测试、回归用例和测试驱动入口 | 对应平台测试文件 |
| `uploads/stickers/` | 内置资源 | 随版本库交付的默认贴纸包；其他运行期用户上传目录不交付 | 各贴纸包 `manifest.json` |
| `third_party/` | 第三方源码/许可 | 随项目固定的第三方组件和许可证；其版权声明不得删除 | 各子目录 `README`、`LICENSE` |
| `docs/` | Markdown / HTML | 架构、配置、API、部署、运维、安全、功能和客户教程 | `docs/客户源码交付使用指南.md`、`docs/Windows远程打包成功经验.md` |

当前快照没有独立的 `h5/` Vue 客户端目录；Web 客户端由 Flutter 的 `web/` 与 `lib/` 源码构建。文档中提及的 H5 域名或 H5 容器，在本快照中指 Flutter Web 静态站点，不能据此认定另含一套独立 H5 源码。

## 三、推荐阅读与部署顺序

1. 阅读 `SOURCE_DELIVERY_README.md`、`SOURCE_DELIVERY.md` 和本文，确认交付范围。
2. 阅读 `docs/产品功能清单-前后台.md`，了解本次源码覆盖的功能域和启用条件。
3. 阅读 `docs/ARCHITECTURE.md`、`docs/CONFIGURATION.md` 和 `docs/API接口完整参考.md`，理解架构、配置与接口。
4. 按 `docs/客户源码交付一键部署手册.html` 或 `docs/客户域名替换与Docker一键交付小白教程.md` 准备客户自有域名、证书和密钥。
5. 在隔离环境完成数据库迁移、后端启动、管理后台和客户端构建。
6. 按 `docs/OPERATIONS.md` 和仓库验收说明完成备份、恢复、回滚及多端验证。

## 四、配置和凭据边界

- 源码包只保留 `.example`、`.sample`、`.template` 等配置模板，不包含可直接使用的生产密码、Token、私钥、证书或签名文件。
- 数据库、Redis、对象存储、支付、短信、推送、地图、音视频和应用商店账号均应由接收方自行申请，并通过私密渠道配置。
- 第一次上线前必须替换示例域名、默认口令和开发环境参数，启用 HTTPS、最小权限、备份、日志脱敏和来源限制。
- Android、iOS、Windows、macOS 和 Web 应分别构建与验收；一个平台通过不能代表其他平台已通过。

## 五、完整性校验

解压后在 PowerShell 中执行：

```powershell
Get-Content -LiteralPath MANIFEST-SHA256.txt | ForEach-Object {
    if ($_ -match '^([0-9A-Fa-f]{64})  (.+)$') {
        $actual = (Get-FileHash -Algorithm SHA256 -LiteralPath $Matches[2]).Hash
        if ($actual -ne $Matches[1]) { throw "哈希不一致：$($Matches[2])" }
    }
}
```

在 Linux/macOS 中可执行：

```bash
sha256sum -c MANIFEST-SHA256.txt
```

校验失败时不要继续部署，应重新获取交付包并通过独立渠道核对压缩包 SHA-256。
