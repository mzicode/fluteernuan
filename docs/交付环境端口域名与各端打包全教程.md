# 交付环境端口、域名与各端打包全教程

本文是客户交付时的端口、域名、反向代理和前端构建总表。技术模块名、Bundle ID、Go module 和 `CUSTOMER_IM_*` 环境变量属于兼容契约，保持不变；域名、密码、证书和生产参数必须替换为客户自己的值。

## 1. 先区分三种环境

不要把三种环境的端口混在一起：

| 环境 | 用途 | API 宿主端口 | 管理后台 | Web/H5 | 客服后台 | 数据库端口 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 本地 `compose.yaml` | 开发和联调 | `8080` | `8082` | 由 Flutter Web 静态服务自行指定 | 由本地开发服务自行指定 | MySQL `3306`、MongoDB `27017`、Redis `6379` |
| 宝塔源码 Docker | 服务器现场构建 | 默认 `18080` | 默认 `18084` | 可选 `--h5-domain`，端口由脚本参数设置 | 可选客服反代 | MySQL `13306`、MongoDB `17017`、Redis `16379` |
| 宝塔预编译交付包 | 推荐生产部署 | `127.0.0.1:18080` | `127.0.0.1:18084` | `127.0.0.1:18083` | `127.0.0.1:18085` | `127.0.0.1:13306/17017/16379` |

生产服务端口只绑定服务器回环地址，由宝塔 Nginx 通过 `80/443` 对外提供访问。数据库和内部容器端口不要在安全组放行。

## 2. 对外域名和反向代理矩阵

推荐使用四个独立二级域名。以下仅为占位示例：

| 业务 | 客户域名示例 | 对外协议 | Nginx 上游 | 对外路径 |
| --- | --- | --- | --- | --- |
| API、WebSocket、媒体 | `api.example.com` | HTTPS/WSS | `127.0.0.1:18080` | `/api/v1`、`/uploads`、`/health` |
| 运营管理后台 | `admin.example.com` | HTTPS | `127.0.0.1:18084` | `/`，后台容器再代理 `/api/` 到 API |
| Flutter Web 页面 | `web.example.com` | HTTPS | `127.0.0.1:18083` | `/`，必须支持 SPA 回退 |
| 客服管理后台 | `kf.example.com` | HTTPS | `127.0.0.1:18085` | `/`，客服容器再代理 `/api/` 到 API |

客户端最终地址：

```text
REST：      https://api.example.com/api/v1
WebSocket： wss://api.example.com/api/v1/ws
媒体：      https://api.example.com/uploads/
健康检查：  https://api.example.com/health
后台：      https://admin.example.com/
Web：       https://web.example.com/
客服：      https://kf.example.com/
```

DNS 必须把四个 `A` 记录都指向同一台服务器公网 IP。安全组只放行 `22`、`80`、`443`；`18080`、`18083`、`18084`、`18085`、`13306`、`17017`、`16379` 不对公网放行。

## 3. 本地 Compose 端口

在项目根目录执行：

```bash
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8080/health
```

本地端口用途：

| 地址 | 用途 | 是否可给公网 |
| --- | --- | --- |
| `127.0.0.1:8080` | API、WebSocket、媒体 | 否 |
| `127.0.0.1:8082` | 运营后台容器 | 否 |
| `127.0.0.1:3306` | MySQL | 否 |
| `127.0.0.1:27017` | MongoDB | 否 |
| `127.0.0.1:6379` | Redis | 否 |
| `127.0.0.1:9090` | Prometheus，启用 `observability` profile 后 | 否 |
| `127.0.0.1:9093` | Alertmanager，启用 `observability` profile 后 | 否 |
| `127.0.0.1:3000` | Grafana，启用 `observability` profile 后 | 否 |
| `127.0.0.1:3200` | Tempo，启用 `tracing` profile 后 | 否 |

模拟器和真机地址不同：Android 模拟器使用 `10.0.2.2:8080`；同一局域网真机使用开发机局域网 IP；浏览器使用 `localhost:8080`。不能把 `127.0.0.1` 写进真机生产配置。

## 4. 生产服务器端口

### 4.1 宝塔预编译包（推荐）

本地构建包：

```powershell
pwsh -File scripts/build-online-prebuilt-package.ps1 `
  -CustomerName "customer" `
  -PackageName "customer-oneclick" `
  -ApiDomain "api.example.com" `
  -AdminDomain "admin.example.com" `
  -H5Domain "web.example.com" `
  -KfDomain "kf.example.com" `
  -H5Port "18083" `
  -AdminPort "18084" `
  -KfPort "18085" `
  -Scheme "https" `
  -InstallDir "/www/wwwroot/customer" `
  -DefaultAdminPassword "替换为强密码"
```

脚本会构建运营后台、客服后台、Flutter Web 和 Linux 后端，并生成 `.zip`/`.tar.gz`。服务器不需要安装 Go、Node.js 或 Flutter。

服务器执行：

```bash
tar -xzf customer-oneclick-时间戳.tar.gz -C /www/wwwroot/customer
cd /www/wwwroot/customer
chmod +x deploy-customer.sh deploy-online-prebuilt.sh scripts/baota_docker_deploy_prebuilt.sh
sudo bash deploy-customer.sh
```

预编译部署参数：

```bash
sudo bash scripts/baota_docker_deploy_prebuilt.sh \
  --admin-domain admin.example.com \
  --api-domain api.example.com \
  --h5-domain web.example.com \
  --kf-domain kf.example.com \
  --admin-port 18084 \
  --api-port 18080 \
  --h5-port 18083 \
  --kf-port 18085 \
  --mysql-port 13306 \
  --mongo-port 17017 \
  --redis-port 16379 \
  --scheme https \
  --write-nginx \
  --admin-password "替换为强密码" \
  -y
```

### 4.2 源码现场构建包

源码包部署使用 `scripts/baota_docker_deploy.sh`，默认只有 API、后台和数据库端口；如要独立 Web/H5 或客服域名，应明确使用对应的预编译包或补充静态产物与 Nginx 配置。不要把源码现场构建模式和预编译包的端口参数混用。

## 5. 宝塔 Nginx 配置逻辑

宝塔负责域名、SSL 和公网监听，Docker 只负责本机上游：

```nginx
# api.example.com
location / { proxy_pass http://127.0.0.1:18080; }
location /api/v1/ws { proxy_pass http://127.0.0.1:18080; proxy_http_version 1.1; }
location /uploads/ { proxy_pass http://127.0.0.1:18080; }

# admin.example.com -> 127.0.0.1:18084
# web.example.com   -> 127.0.0.1:18083
# kf.example.com    -> 127.0.0.1:18085
```

`scripts/baota_docker_deploy_prebuilt.sh --write-nginx` 只写反向代理，不接管宝塔申请的证书。SSL 证书、`listen 443 ssl`、HTTP 到 HTTPS 跳转由宝塔站点管理；不要在交付包里重复写证书路径。

逐域名检查：

```bash
curl -fsS https://api.example.com/health
curl -I https://admin.example.com/
curl -I https://web.example.com/
curl -I https://kf.example.com/
docker compose --env-file .env.bt -f compose.bt.yaml ps
```

## 6. 各端构建和打包

### 6.0 前端开发端口

开发端口和生产容器端口不是一回事。开发服务只给本机或局域网联调使用：

| 前端 | 默认开发地址 | 配置来源 | API 代理 |
| --- | --- | --- | --- |
| 运营后台 `admin/` | `http://localhost:8082` | `admin/.env.*` 的 `VITE_PORT`，默认 `8082` | `VITE_API_PROXY_URL`，默认 `http://127.0.0.1:8080` |
| 客服后台 `admin-kf/` | `http://localhost:4273` | `admin-kf/vite.config.ts`，默认 `4273` | 通过 Vite 配置或同源代理访问 `/api/v1` |
| Flutter Web 调试 | `http://localhost:5175` | `flutter run --web-port` | Dart Define 指向 `8080` |
| 独立 Vue H5 | 当前不存在 `h5/` 目录 | 合同补齐后再定义 | 约定 `VITE_API_BASE_URL` |

开发服务启动示例：

```powershell
# 运营后台
cd admin
$env:VITE_PORT="8082"
$env:VITE_API_PROXY_URL="http://127.0.0.1:8080"
pnpm dev

# 客服后台（另开终端）
cd admin-kf
pnpm dev -- --host 0.0.0.0 --port 4273

# Flutter Web（另开终端）
flutter run -d chrome --web-port 5175 `
  --dart-define=CUSTOMER_IM_SERVER_URL=http://localhost:8080 `
  --dart-define=CUSTOMER_IM_WS_URL=ws://localhost:8080/api/v1/ws
```

开发端口发生冲突时只修改开发服务端口和对应代理地址；不要把 `4273`、`5175` 当成生产 Nginx 端口，也不要为了省事修改后端容器内部 `8080`。

### 6.1 Flutter Web

Flutter Web 是当前工作区实际交付的 Web 客户端。独立 `h5/` 目录当前不存在，不要执行 `cd h5`；需要独立 Vue H5 时必须先补齐源码目录和构建契约。

```powershell
flutter pub get
flutter build web --release --no-web-resources-cdn `
  --dart-define=CUSTOMER_IM_SERVER_URL=https://api.example.com `
  --dart-define=CUSTOMER_IM_WS_URL=wss://api.example.com/api/v1/ws `
  --dart-define=CUSTOMER_IM_PUBLIC_H5_URL=https://web.example.com `
  --dart-define=CUSTOMER_IM_BOOTSTRAP_URL=https://api.example.com/api/v1/client/bootstrap
```

产物：`build/web/`。复制到 Web 容器的 `web-dist/` 或 Nginx 静态根目录，SPA 必须回退到 `index.html`。

### 6.2 运营管理后台

```powershell
cd admin
pnpm install --frozen-lockfile
$env:VITE_BASE_URL="/"
$env:VITE_ACCESS_MODE="frontend"
$env:VITE_API_URL="/api/v1"
$env:VITE_API_BASE_URL="/api/v1"
pnpm build
```

产物：`admin/dist/`，复制到 `admin-dist/`，由 `admin.example.com` 的 `127.0.0.1:18084` 提供。

### 6.3 客服后台

```powershell
cd admin-kf
pnpm install --frozen-lockfile
$env:VITE_API_BASE_URL="/api/v1"
$env:VITE_USE_MOCK="false"
pnpm build
```

产物：`admin-kf/dist/`，复制到 `kf-dist/`，由 `kf.example.com` 的 `127.0.0.1:18085` 提供。

### 6.4 Android APK

```powershell
pwsh -File scripts/build-online-android-apk.ps1 `
  -ServerUrl "https://api.example.com" `
  -WsUrl "wss://api.example.com/api/v1/ws"
```

交付前检查 APK 内的 REST、WS、Bootstrap 和媒体地址都指向同一个客户 API 域名。Android 签名文件、密钥和 Firebase 配置不得放进源码包。

### 6.5 Windows

```powershell
pwsh -File scripts/build-online-windows-installer.ps1 `
  -ServerUrl "https://api.example.com"
```

若只需要未安装包：

```powershell
flutter build windows --release `
  --dart-define=CUSTOMER_IM_SERVER_URL=https://api.example.com `
  --dart-define=CUSTOMER_IM_WS_URL=wss://api.example.com/api/v1/ws
```

### 6.6 iOS 和 macOS

```bash
flutter build ios --release \
  --dart-define=CUSTOMER_IM_SERVER_URL=https://api.example.com \
  --dart-define=CUSTOMER_IM_WS_URL=wss://api.example.com/api/v1/ws

flutter build macos --release \
  --dart-define=CUSTOMER_IM_SERVER_URL=https://api.example.com \
  --dart-define=CUSTOMER_IM_WS_URL=wss://api.example.com/api/v1/ws
```

iOS/macOS 还需要客户自己的 Team、Bundle 签名、推送、RTC 和商店配置；命令成功不代表已经具备发布资格。

## 7. 构建产物和域名一致性

每次换 API 域名都必须重新构建所有编译期注入地址的客户端。不能只改 Nginx 域名后继续使用旧的 Flutter Web、APK 或 Windows 包。

交付记录至少保存：

| 产物 | 目录/文件 | 必须核对 |
| --- | --- | --- |
| Flutter Web | `build/web/`、`web-dist/` | API、WS、Bootstrap、媒体地址 |
| 运营后台 | `admin/dist/`、`admin-dist/` | `/api/v1` 同源代理 |
| 客服后台 | `admin-kf/dist/`、`kf-dist/` | `/api/v1` 同源代理、Mock 关闭 |
| Android | `artifacts/online-android-apk-*` | REST、WS、签名、版本 |
| Windows | `build/windows/x64/runner/Release` | REST、WS、安装器版本 |
| iOS/macOS | `build/ios`、`build/macos` | 签名、推送、应用 ID、地址 |

## 8. 不同端口时的排查顺序

1. `docker compose ps` 或 `compose.bt.yaml ps` 确认容器健康。
2. 从服务器本机 `curl http://127.0.0.1:<端口>/health`，确认上游端口。
3. 从服务器本机 `curl -I http://127.0.0.1:<端口>/`，确认静态前端端口。
4. 检查宝塔站点反代目标是否与端口表一致。
5. 检查 DNS、SSL、CORS 和 WebSocket Upgrade。
6. 检查客户端编译时注入的 API/WS 地址，不要只看浏览器地址栏。

不要用 `docker compose down -v` 做普通重启；该命令可能删除数据库和上传卷。更新前先备份 `.env.bt`、数据库和上传目录。
