# 手机号账号与暖邻ID规则

更新日期：2026-09-12

## 一、产品规则

1. 用户名不再作为公开社交账号使用。
2. 登录账号统一为中国大陆手机号。
3. 注册时手机号同时写入 `username` 和 `phone`。
4. 手机号必须为有效的中国大陆 11 位手机号码。
5. 手机号只用于注册、登录和账号认证，不在公开资料卡中展示。
6. `short_id` 作为“暖邻ID”，用于用户识别、复制、分享和后续邀请码能力。
7. 用户资料、二维码名片、分享名片和设置页只能展示暖邻ID，不能展示手机号型用户名。
8. 设置页面不再显示“未绑定手机”。

## 二、前端当前实现

### 注册

- 注册账号输入框显示为“手机号（11位）”。
- 输入框只允许输入数字，最多 11 位。
- 使用 `isValidMainlandChinaMobile` 校验手机号格式。
- 注册请求中：
  - `username` = 用户输入的手机号。
  - `phone` = 用户输入的手机号。
  - 短信注册启用时继续提交 `sms_code`。
- 注册页不再允许用户设置英文用户名。
- 注册页不再使用邮箱作为主要注册账号。

### 登录

- 登录账号输入框显示为“手机号”。
- 输入框只允许输入数字，最多 11 位。
- 登录前强制校验有效的中国大陆 11 位手机号。
- 登录接口仍使用后端现有的 `username` 参数，参数值为手机号。

### 自己的资料和设置页

- 隐藏原用户名编辑和展示入口。
- 隐藏手机号绑定状态和“未绑定手机”提示。
- 设置页顶部只显示：`暖邻ID: short_id`。
- 个人资料页显示并支持复制暖邻ID。
- 复制邀请链接时使用 `short_id` 作为邀请标识。

### 他人资料、二维码和分享

- 查看他人资料时读取 `short_id`，不展示接口返回的 `username`。
- 资料卡字段名称显示为“暖邻ID”。
- 二维码名片下方显示 `@暖邻ID`。
- 分享名片和复制名片文本显示 `@暖邻ID`。
- 二维码实际识别目标仍使用用户 UUID，避免暖邻ID修改或格式变化影响已有扫码逻辑。

## 三、后端接口要求

后端需要确保以下接口稳定返回 `short_id`：

- 注册成功响应。
- 登录成功响应。
- 当前用户资料接口。
- 查看其他用户资料接口。
- 联系人或用户搜索接口中需要展示暖邻ID的用户对象。

注册接口需要保证：

1. 校验 `username` 是有效且唯一的手机号。
2. 校验 `phone` 与 `username` 完全一致。
3. 注册成功后直接完成手机号绑定。
4. 同一手机号不能重复注册。
5. 为新用户生成唯一、稳定的 `short_id`。

登录接口需要保证：

1. 支持通过手机号型 `username` 登录。
2. 旧的非手机号用户名是否继续兼容，由后端单独决定；新客户端不会提供旧用户名输入方式。

暖邻ID需要保证：

1. `short_id` 全局唯一。
2. `short_id` 不包含手机号等隐私信息。
3. `short_id` 可以用于后续邀请码、用户搜索和分享链接参数。
4. 接口不得把手机号型 `username` 当作公开账号返回给其他用户展示。

## 五、验收标准

1. 注册输入少于或多于 11 位手机号时不能进入下一步。
2. 注册输入无效号段时显示手机号格式错误。
3. 注册请求中的 `username` 和 `phone` 内容一致。
4. 登录页不能输入字母、下划线或超过 11 位数字。
5. 使用正确手机号和密码可以正常登录。
6. 设置页不显示手机号和“未绑定手机”。
7. 自己的资料页只显示暖邻ID，不显示手机号型用户名。
8. 查看其他用户资料时只显示暖邻ID。
9. 二维码名片和分享名片显示 `@暖邻ID`。
10. 复制邀请链接时使用暖邻ID，不使用手机号。
